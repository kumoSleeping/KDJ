# KDJ 视频

用户在 KDJ 里交给你画面的事。你做出来的东西是一个 **.kdjv 视频工程**：曲库里的一行，标着「工程」，点开就像普通视频一样播放，
实际上是按你写的剪辑表把本机文件拼起来。工程是非破坏的：原文件不动，改工程就是改剪辑表。

## 总则

- 这些画面是用户在 DJ 现场放给观众看的。黑屏、画面和歌错位、水印、和歌无关的画面，在现场都是事故。
- 歌词字面的意思不是画面的主题。动画歌的画面主题是那部动画，偶像歌是那个偶像，游戏歌是那款游戏。
- 你听不到歌。段落和时间靠 `kdj_library_get` 的小节线、`kdj_align` 的对齐、用户标的时间，不靠猜；猜了就在报告里说是猜的。
- **素材里有这首歌的声音，就按 `kdj_align` 的方案放画面**（`references/align.md`）。不要用能量、段落或自己写的脚本另排一套。
- 判断画面（有没有字幕、合不合适）一定先用 `kdj_peek` 看，不凭标题猜。
- 下面的分类和步骤是默认路线，不是限制：用户的话和默认步骤不一样时，以用户的话为准。
- 原文件只读：不覆盖、不移动、不改名用户的文件。新东西只写在工作目录、你保存的 .kdjv 和用户同意的导出文件，
  而且只写进已有的文件夹。用户明确要求复制、改名文件或新建文件夹时，按系统提示用 bash，不要用保存工程或导出代替，也不要绕过路径限制。

## 分类

每一类一个文件，在 `references/` 下，到了那一步就读它。文件里按这几节写，没有的节就是这一类用不着：
认得出 / 用户需确认 / 禁止事项 / 常见操作、审美规范 / 最简流程 / 出错时 / 交付、进入下一阶段。

| 类 | 什么时候读 | 文件 |
|---|---|---|
| 用户需求确认 / 初期规划 | 每个视频任务最先读：认出是哪一类，用户说了什么、还要问什么 | `references/plan.md` |
| 重要任务确认 | 交方案时；大量下载、导出、计划变了时 | `references/confirm.md` |
| 确定素材：歌曲查询 | 查这首歌出自哪里、段落在哪 | `references/song.md` |
| 确定素材：VJ 素材查找 | 要找视频素材时 | `references/footage.md` |
| 可视化生成 | 用 KDJ 自己的可视化出画面，不搜、不下载 | `references/visualizer.md` |
| VJ 剪辑（标准） | 找这首歌自己的画面按段落剪，效果从只剪拼到配合 drop 的强效果 | `references/cut.md` |
| VJ 剪辑（用户定制） | 用户指定了素材或结构；拖来歌和视频要对上；翻唱、remix 重剪；DJ 歌单 | `references/custom.md` |
| 音画对齐 | 素材里有这首歌的声音时（找素材和剪辑都要） | `references/align.md` |
| 修改已有工程 | 改一个已有的 .kdjv | `references/edit.md` |
| 工程格式 | 写或改 .kdjv 之前 | `references/kdjv.md` |

一次任务的顺序：需求（plan）→ 查歌（song）→ 找素材并给候选对齐（footage、align）→ 交方案（confirm）→ 下载 →
剪辑或可视化（cut / custom / visualizer）→ 保存、播放、报告。可视化跳过找素材和下载。
