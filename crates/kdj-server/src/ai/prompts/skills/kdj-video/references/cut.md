# VJ 剪辑（标准）

找这首歌自己的画面，按段落剪成整首或 short。效果分三档：只剪拼 / 段落处转场 / 配合 drop 的强效果。

## 认得出

「做个 VJ」「剪个视频」「配画面」，用户没有指定素材和结构时默认是它。「简单剪一下」「剪个动画的」「不要特效」「干净点」
「快点出一个」，或者用户只要一个能放的画面、没提效果，也是它，效果选「只剪拼」。

## 用户需确认（放进方案）

- 素材方向：列出找到的具体候选，可多选（`footage.md`）。
- 效果多少：只剪拼 / 段落处转场 / 配合 drop 的强效果。
- 画面比例。
- 整首还是 short：素材往往只有 TV size（约 90 秒），整首歌更长，用户没说做多长就问；只有 short 时中间怎么补
  （原作剪辑 / 现成的长版 MAD / 其他）。
- 字幕还是裁切：只有带字幕的版本时一定问（裁掉字幕区 / 接受字幕 / 不用带字幕的）；用户没提字幕也问一句。
- 标准裁切会切掉边缘：素材比例和画布不同、人物又靠边时，切到脸比留黑边更糟——在方案里问。
- 素材下到哪、交付方式。

## 禁止事项

- **VJ 的节奏感来自叠在上层的切换和效果，不是把对上的素材拆碎重排。** 底下那条轨按 `kdj_align` 的方案原样走（`align.md`），
  画面里的动作才落在它自己的音乐上。曾经有一次 AI 没用对齐方案、按能量把 NCOP 拆成二十几个镜头重排，还给单个镜头调到 0.6 倍速，
  结果整片的动作都和歌错开，用户一眼就看出来了。
- 「只剪拼」这一档不加转场、滤镜、字卡：用户要的是快和干净，不是创意，每多一个都是噪音。
- 「简洁」不是「随便」：剪点仍然落在小节线上，画面仍然必须是这首歌自己的。
- 一次 FFmpeg / Remotion 只渲染需要的那一小段，不要把整首歌重编码一遍——整体由工程拼起来。

## 审美规范

- 效果越多，下得越多、渲染越久，方案要越清楚。
- 效果服务于歌的段落（副歌进来时的切换、间奏的转场、drop 的冲击），不是为了显得复杂。
- 自己剪的剪点落在小节线上（`kdj_library_get` 的 downbeats、bpm）；从素材里取 `gaps` 时不重复同一段。
- 「只剪拼」：只写剪辑表——切、拼，段与段的交接默认用淡入淡出（交叉淡化约 1 拍，见 `kdjv.md`），用户要硬切才硬切；等比放大铺满画布、居中裁切（选了裁字幕就只裁掉字幕那一条）。
- 画布尺寸由方案里的比例定（16:9 → 1920×1080，9:16 → 1080×1920，1:1 → 1080×1080），写进 `canvas`；帧率跟底下那条轨的主素材。

## 常见操作：做工程

1. 读 `kdjv.md`，按格式写剪辑表。时间都是秒；`in`/`out` 是素材里的位置，`at` 是放在成片里的位置。
2. 能直接用剪辑表表达的（剪、拼、换一段、叠一层、调速、音量、淡入淡出、位置缩放透明度）就只写剪辑表。
3. 剪辑表表达不了的效果（转场、遮罩、抠像、调色、模糊、推拉、字卡、动态图形），先把那一小段渲染成一个片段文件，
   再在剪辑表里引用它：像素处理用 `kdj_ffmpeg`，字、图形、版式动画用 `kdj_remotion_render`。
   FFmpeg 的滤镜和 Remotion 的组件怎么写由你自己决定。要放进工程的片段：
   - 尺寸、帧率和工程画布一致；
   - 不透明的用 H.264（yuv420p）的 `.mp4`；只有画面、要盖在别的轨道上的，用带透明的 ProRes 4444 `.mov`；
   - 盖在两段交界上的过渡片段放在上一层轨道，`muted: true`，渲染时不带声音（声音由底下两段照旧放）；
     它每一帧都要和底下同一时刻放的画面接得上，否则盖上去会跳。
   渲染出来的文件在工作目录的 `renders/` 里，用它的绝对路径作为 `src`；在工程的 `generated` 里记下它是怎么做的（工具和参数），
   以后可以重做。
4. 用 `kdj_project_save` 保存到曲库文件夹（方案里定的文件夹，用 `kdj_folders` 找到它的路径；没定就放在第一个素材所在的文件夹）。
5. 用 `kdj_play` 播放它（用 `kdj_library_list` 找到这一行的 id）。
   不要先 `kdj_project_render`：KDJ 点开工程就实时预览，改了工程再放也一样；它只在用户要预先渲染时用。

## 最简流程

1. 下载选中的素材（`footage.md`；「只剪拼」一般 1–3 个）。
2. 每个素材都 `kdj_align`，把对上的区间原样铺在底下一条轨道（`align.md`）。
3. 只有 `gaps` 按段落和小节剪。
4. 效果叠在上层；剪辑表做不了的渲染一小段。
5. 有要用户定的地方（空档怎么补、交界怎么接、效果多强）：按推荐铺好存成草稿，用时间轴问（`confirm.md`「剪辑草稿确认」）。
6. 保存、播放，交报告。

## 出错时

- `kdj_project_save` 先检查再写：没通过就不保存，照着报错改好再存。
- 刚保存的工程曲库要一两秒才收录，`kdj_library_list` 没找到就再查一次。
- 渲染失败时看返回的最后几行，改了再渲染。
- 下载失败、对不上、找到的和方案不一样：先 `ask_user`（`confirm.md`）。

## 交付 / 进入下一阶段

- 默认保存 .kdjv、播放，让用户先预览。导出 MP4 要用户同意过（`confirm.md`）。
- 做完在最后收尾的那段话里交报告（它会一直留在用户屏幕上，不用 `tell_user`）：
  1. 成片每一段：成片时间 ← 用的素材和它里面的时间，用的是哪套对齐方案或按小节自己剪的（`align.md`）；
  2. 对不上 / 空档：在哪、多长、怎么处理的；
  3. 裁切方式、素材画质（哪个低于目标分辨率、实际用了多少）、用了哪些效果、放在哪里、哪些地方是估的、哪一步没按方案；
  4. 下一步：要不要导出。
