# 音画对齐

画面和歌错位，在现场就是事故，而你听不到歌，只有 `kdj_align` 听得到。找素材（`footage.md`）和剪辑（`cut.md`、`custom.md`）都按这里做。

## 最简流程

1. **每个含这首歌声音的素材都先 `kdj_align`**（原版、TV size、NCOP/NCED、整体变速的 remix 都算），下载后用本地文件再对一次。
   B 站和曲库的素材在方案之前就能对；YouTube 在线视频对不了，要下载后才能对：方案里写明「下载后才对齐」，不要写成已对上。
2. **对上的区间原样铺，不拆**：方案里的一个 segment 就写成一个片段——`at` = `ref_at`，`in` = `video_in`，`out` = `video_out`，
   `speed` = `speed`。
3. **只有 `gaps`（方案没覆盖的段）才按小节自己剪**。

## 禁止事项

- **每个素材只对这一次，拿到的 plans 就是结论**：`ref` 用这首歌在曲库里的那一行或用户给的歌文件，不截取歌的片段、
  不把素材变调变速、不换个参考再对（工作目录里的文件会被拒绝）；方案没覆盖到的就是 `gaps`。
  曾经有一次 AI 拿到了整首的方案，又把歌切成五六段、把 NCOP 变调变速，前后对了十一次去找段落，还丢掉了第一次就对上的副歌候选，
  方案前的时间大半耗在这里。
- 不要把对上的区间拆成镜头重新排，不要给单个镜头另调速度。要加切换、闪白、插入镜头，就放在上面一层轨道，下面这条照着方案走，
  画面才和唱的、跳的对得上。
- **不许因为「相似度低」就丢掉候选、改用自己算的偏移。**
- 不写脚本分析音频（切片段、算能量、算相关、变调重对）：歌里有什么，只问 `kdj_align` 和 `kdj_library_get`。

## 常见操作

- `ref_at` 是歌文件里的时间：歌在工程里不是从 0 秒、从头放的（DJ 歌单里后面的歌、只取了一段）时，`at` 要加上歌片段的 `at` − `in`，
  超出歌片段 `in`–`out` 的部分截掉（`in`/`out` 相应调整）；歌片段本身不变速。
- **`auto` 为 true（verified）直接用。`auto` 为 false（melody / partial）是候选，不是错**：照候选铺好、保存、`kdj_play`，
  在报告里写明哪几段是候选，请用户试听确认（`kdj_peek` 看不出音画是否同步，截帧代替不了试听）。
- **一个方案只管它自己 segments 覆盖的那一段**。几套方案覆盖不同段落时一起用（例如 `melody-1` 管前半首、`melody-2` 管最后一段副歌）。
  核对候选只核对它覆盖的那一段，不要拿整段视频去比整首歌。
- 整首歌对一次 `kdj_align` 就知道哪几段有画面，其余就是 `gaps`。

## 出错时

- `matched` 为 false 才是对不上：告诉用户，改成按小节剪，不要硬拼。
- YouTube 下载后对不上：回来 `ask_user`。
- 用户说某个画面放的位置不对：先回到 `kdj_align` 的方案，对照那一段换用另一套方案，不要凭感觉挪。

## 交付

报告里每一段写清用的是哪套方案（`id`、`evidence`），哪些段是按小节自己剪的。
