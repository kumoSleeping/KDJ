# 步骤 2：彩色波形、文件夹模式、设置与视频板块

这一步做了四件事：把 RGB 波形从「三团色块」改成真正的 DJ 波形；把曲库从一大坨
文件改成映射到真实目录的文件夹模式；把设置页从一堆面板改成正常的条目列表；
把视频板块补成和下载板块同构的样子。

下面记的是**坑**和**量出来的结论**，不是功能清单——功能看 `docs/00-architecture.md`。

---

## 一、RGB 波形：三次做错才做对

### 错法 A：三条包络各画各的高度，用 `mix-blend-mode: screen` 叠色

第一版就是这么写的。结果不是波形，是**三团上下对称的色块套在一起**——蓝的在
中间、红绿从两边探出头。原因很直白：波形只该有**一个**高度（这一刻有多响），
把三个频段各画成一条对称包络，等于画了三个波形叠在一起。

查了 [libdjwaveform](https://github.com/turbo/libdjwaveform)（专门做 Serato 那种
彩色波形的库）之后确认正确模型是：

> STFT → 每一帧产生**一列**：垂直高度 = 幅度，颜色 = 该列的频谱构成。

**高度只有一个，颜色才是分频的结果。** 这是整件事的关键，其余都是调参。

### 错法 B：三段幅度用同一个尺度直接当 RGB（最朴素的"Serato 做法"）

改成一列一根柱子之后，第一版配色是三段幅度按同一尺度归一。渲染出来**整首全是
绿的**。原因：中频段（200 Hz–1.5 kHz）带宽最宽，能量天然最大，于是每一列的最大
通道永远是绿。

### 错法 C：三段各按自己的 P95 归一

去掉了频段之间的系统偏置，但**整首发白**。原因：三段的响度是高度相关的
（一起大声一起小声），各自归一之后每一列三个通道都接近 1，混出来就是白。

### 对的做法：占比 vs 全曲常态占比

```
share[b][t] = mag[b][t] / Σ_b mag[b][t]      # 除掉共同的响度
ref[b]      = median_t(share[b])              # 本曲的"常态"，用中位数不用均值
dev[b][t]   = (share[b][t] / ref[b]) ** 6     # 只有比常态更强的频段才亮
rgb[·][t]   = dev[·][t] / max_b(dev[b][t])    # 按最大通道拉满，只留色相
```

γ 是必须很大的：占比的偏离量本身很小（0.45 → 0.50 这种级别）。实测 γ=3 出来是
一片淡彩，γ=12 会糊成大色块，**γ=6 刚好**——鼓点段红、人声段绿、镲密的段蓝。

代价要说清楚：颜色是**相对本曲**的，两首曲子的同一个颜色不代表同样的绝对频谱。
但波形是拿来看单曲结构的，段落之间分得开比跨曲可比更有用。

### 另外两个不平滑就翻车的地方

1. **配色前必须沿时间轴做滑动平均**（窗口 = 列数/128）。一格才 200~300 ms，
   底鼓和踩镲会逐格交替，不平滑的话每根柱子颜色都跳，画出来是彩色噪点。
   试过加大到 列数/48 和 列数/24：更平滑，但也把 share 拉回中位数、
   dev 趋近 1，颜色又变淡。**列数/128 是清晰度和稳定性的平衡点。**
2. **高度不能只除 P99**。现代母带压完之后整首 RMS 都挤在 0.6~1.0，
   画出来是一条实心带（实测 amp 均值 0.858）。改成 P5 当地板的对比拉伸
   之后均值降到 0.51，起伏才回得来。

### 渲染用 canvas 不用 SVG

几百到上千根柱子如果各是一个 `<rect>`，切曲时 DOM 会明显卡一下。canvas 一次
`fillRect` 循环画完，并且**按像素列**遍历（数据比像素多时取区间最大值，
少时铺满几个像素），放大缩小都不会有摩尔纹或空隙。

播放头和已播遮罩留在 DOM 层，所以位置每 200 ms 变一次不会触发 canvas 重绘。

### 坑：缓存文件名要带版本号

波形结果按 `(id, buckets, mtime)` 缓存到 `data/waveform/`。这次 payload 从
「三条包络」变成「每列一色」，如果不在文件名里加 `v2`，旧缓存会以旧结构原样
返回，前端拿到没有 `amp` 的对象只会画出一片空白。

## 二、文件夹模式

### 为什么落到真实文件系统，而不是数据库里的分组

DJ 出场前要把一套歌拷进 U 盘、要用 Rekordbox / Serato 再读一遍。虚拟分组到那一步
就没了。所以移动就是 `shutil.move`，链接就是 `os.link`，改名就是 `Path.rename`。

### 坑 1：越界校验必须做两道

`dest` 只做归一化路径检查，能被「曲库里放一个指向 `/etc` 的符号链接」绕过；
只做 realpath 检查，又会和数据库里**没有解析过符号链接**的 path 对不上
（`normalize_path` 只做 expanduser + abspath + normpath，注释里写明了不做 realpath，
因为下载器传进来的路径和扫描出来的路径必须对得上）。

所以两道都要过：归一化路径在某个根下 **且** realpath 在该根的 realpath 下。

同前缀的兄弟目录也是个真坑：`/Users/me/Music-evil` 会被字符串前缀比较放过，
用 `Path.is_relative_to` 才挡得住。三条都写进了测试。

### 坑 2：`rebase_paths` 不能用 SQL 的 `replace()`

目录改名之后，它下面每一首歌的 path 都失效了，必须整枝跟着改。图省事写成
`UPDATE tracks SET path = replace(path, ?, ?)` 会替换字符串里**每一处**匹配：
`/music/set1/set1/a.mp3` 这种目录并不罕见，一改就错。改成在 Python 里只换前缀。

### 坑 3：老库的 `library_dirs` 是空的

文件夹模式上线之前扫过歌的库，`library_dirs` 是空的，文件夹树会一片空白，
而歌明明就在列表里摆着。补了两条：

1. `POST /library/scan` 把显式扫描的目录自动登记成曲库根；
2. `library_dirs` 为空但已有曲目时，`infer_roots()` 反推一次并写回设置。

反推的第一版取**所有曲目路径的最近公共祖先**，在真实库上直接失败：曲目横跨
下载目录（`~/Music/KumoDeck/netease`）和自建歌单目录（`~/git/djay/邦多利歌单`），
公共祖先退化成 `~`，被"深度 < 4 不当根"的保护挡掉，于是还是一片空白。

改成**每个存歌的目录各自往上退一层**，退到家目录 / `/Users` / `/Volumes` / `/`
就不再往上。真实库上得到 `~/Music/KumoDeck` 和 `~/git/djay` 两个根，正确。

### `.kumodeck.json`：每个目录一份，不是根目录一份

顺序存在每个受管目录里的 `.kumodeck.json`（`{version, order: [子目录名]}`）。

为什么每目录一份：**清单跟着文件夹走**。出场前把 `温州/` 整个拷进 U 盘，顺序也
一起过去了；把某个子目录挪到别的根下面，它内部的顺序照样成立。一份中心清单
做不到这两点，而且一旦和磁盘不同步就整棵树错位。

为什么不进 SQLite：数据库在 app 的 userData 里，换台电脑就没了；而 DJ 的目录
本来就是要跨机器搬的。

容错：清单里有磁盘上没有的名字（被删/改名）直接丢弃；磁盘上有清单里没有的
（新建的）按名字排在后面；文件读坏了只退回按名字排序，不让整棵树打不开。
这三条都有测试。

### 硬链接：一首歌进两个 set 不多占空间

`os.link` → 失败退 `os.symlink` → 再退 `shutil.copy2`，然后 `upsert_file()` 建新行 +
`clone_metadata()` 把分析结果和评分/备注抄过去——链接的两端是同一份音频，
重新分析必然得到同样的 BPM 和调号，让用户为了一个链接再等一次分析没有道理。

`Track.link` 由 `st_nlink > 1` / `is_symlink()` 现算，前端在标题前打个链接图标。
它回答的是用户真正会问的那个问题：「这首为什么出现两次？」

### 同名文件绝不覆盖

两个 set 里同名不同 mix 的文件非常常见（`Track - Artist.mp3` 可能是 radio edit
也可能是 extended），静默覆盖会直接丢掉一首歌。同名一律加 ` (2)`、` (3)`。

## 三、设置页与视频板块

### 设置页：条目，不是面板

原来每组设置各自装在一个带红色角标的面板里，账号还是四张卡片、每张一个红底
实心的「扫码登录」按钮——整页都是红块，看着像仪表盘不像设置页。

改成一列条目：左边名字 + 一句说明，右边控件；分组标题只是一行小字。宽度收在
46rem 并居中——设置项都是「一句话 + 一个控件」，拉满整屏之后标签和控件会离得
老远，眼睛要来回扫。

登录按钮改成 ghost 文字按钮，状态用一行小字（未登录/过期染暖色）而不是彩色标签。

顺手删了一条从后端漏到 UI 上的实现细节文案：
`"SoundCloud 未启用，请先在设置里打开 soundcloud_enabled。"`——用户不需要知道
配置项的变量名。

### 视频：和下载板块同构

- 右侧接上同一个 `QueuePanel`（同一个 download store，视频任务本来就在里面）
- 顶栏加了目录小按钮 + 格式选择 + 「加入队列」，和下载板块一一对应
- 视频单独一个 `video_download_dir`（默认 `~/Downloads/KumoDeck`）：视频动辄几百 MB，
  混进音乐目录会被曲库扫描一起扫走
- 容器格式可选 MP4 / MKV / MOV，默认 MP4；勾了「只要音轨」就固定 m4a，
  并且落到**音乐**目录——那是要进曲库的素材
- 删掉了「视频板块是次要功能：现场素材、Live 版、官方 MV 的音轨常常只有 B 站有」
  这种人尽皆知的说明文字

## 验证

```
npx tsc --noEmit                      # 0 error
npm run build                         # 通过
sidecar/.venv/bin/python -m pytest sidecar/tests -q     # 74 passed
sidecar/.venv/bin/python scripts/smoke.py               # 19/19
```

`scripts/smoke.py` 里新加的「文件夹：树 / 新建 / 移动 / 链接」是一条**真实文件系统
上的端到端**检查：扫描登记根目录 → 建子目录 → 移动（确认文件真的到了新路径）→
链接（确认 `methods` 里是 `hardlink`）→ 往 `/tmp` 搬（确认被 400 挡下）。

单元测试盖的是纯函数，这条盖的是「路由 + 真实文件系统 + 数据库」三者的接缝——
上一步的 WebSocket 事故就是只测了单元、没测接缝。
