# AI 做视频：四种做法、方案确认和这一轮的修复

起因是 2026-10-19 一次 Agent Mode 做 VJ 的会话（`<data>/ai/sessions/2026-10-19T04-15-02-733Z_….jsonl`）：用户要给曲库里的
《$・¥・€》（动画《FX战士久留美》的 ED）做一个 VJ，想要的是动画的画面；AI 没有问，按歌词字面意思定成「金钱」主题，
YouTube 下载失败后换成 B 站的金色粒子和隧道素材，做出 112 秒和歌毫无关系的工程。规则在 `crates/kdj-server/src/ai/prompts/skills/kdj-video/`，这里记为什么这样定。

## 那一次出了什么问题

| 问题 | 根子 |
|---|---|
| 没问风格就定了「金钱」主题，动画、官方无字 ED/OP、用户的 vj 文件夹这些线索都看到了却往反方向理解 | 提示词只让 AI「其他时候直接做」，ask_user 只用于「几个版本挑一个」 |
| 搜的是货币素材，下的是粒子和隧道 | 没有「计划变了先回来问」 |
| 「无字幕」是按标题猜的，副歌时间是按 BPM 分段猜的 | 模型（deepseek-v4-pro）看不到图片；没有让用户标段落 |
| 下载进了用户整理的 vj 文件夹 | 没有在下载前确认去处 |

04:15 的新会话不记得它。

## 四种做法

`SKILL.md` 里是总表，每种一个文件（`references/preset-*.md`），写法都一样：认得出 / 你要意识到 / 你会做的 / 方案例 / 报告例。
用例子带出行为，而不是写死规则；做法是默认路线，用户的话优先。只有两条是硬的：用户确认前不下载、不渲染；不用和歌无关的素材。

| 做法 | 搜素材 | 效果 | 开工前问 |
|---|---|---|---|
| 完整 VJ（默认） | 按素材顺序，要下载 | 可以有 | 全套方案 |
| 简洁剪辑 | 只用原作和原 MV/PV，最短路径 | 只剪、拼、标准裁切 | 比例、长度、字幕或裁切、对不上的部分；做完交报告 |
| 音视频合并 | 只在没给视频时找原 MV / NCED | 没有 | 有空档时：保留黑屏还是填、填多少（头尾冗余 / 全部）、用什么填（原作随机剪辑 / 可视化 / 其他） |
| 可视化 | 不搜、不下载 | KDJ 可视化 | 比例、范围、直接导出还是放进 .kdjv |

素材顺序（用户没指定时）：原作的 NCOP/NCED、PV、正片 → 歌的原 MV、官方 PV、Live → 曲库里已有的这首歌的 VJ/MV → KDJ 可视化。
同一首歌有几种画面（动画 MV / 真人 MV / PV / Live）时列出来让用户选；翻唱要问用原曲 MV 重剪、原作画面、翻唱自己的视频还是可视化；
remix 要问是否按 remix 的结构和 drop 重剪、要不要更强的效果。同人二创一般由用户指定，不写进默认顺序。

## 工具上的改动

- **一个请求一个会话**（`ai/mod.rs` 的 `prompt`）：AI 空闲时的一句话先开新会话；补充（`follow`）并进当前会话；历史里点了
  「继续」之后的第一句接着那个会话。开新会话后把设置里的模型和推理强度再交给 pi。设置 → AI 有「会话历史」。
- **方案一起确认**（`ask_user` 的 `preview` 和 `questions`）：一个气泡里先写 AI 打算怎么做，下面几个问题各一排选项，一个「确定」
  一起提交，返回 `answers`；关掉或「暂停」返回 `cancelled`。旧的单问题写法不变。
- **非视觉模型**（`kdj-tools.ts` 的 `before_agent_start`）：当前模型不收图片时，每一轮系统提示末尾加一行——你是非视觉模型，
  拒绝剪辑和 VJ 这类视频请求，用一句 tell_user 说明后结束；只用可视化的可以照做。`kdj_peek` 不再把图片交给它。
  按 pi 的模型表，deepseek-flash 收图片，deepseek-v4-pro 不收。
- **对齐的空档**（`kdj_align`）：每套方案多一个 `gaps`（参考曲里没有画面的段，start / end / length，0.5 秒以下的缝不算）。
- **导出**（`kdj_project_export`）：把 .kdjv 渲染后复制成曲库文件夹里的一个 MP4，不覆盖。
- **可视化**（`kdj_visualizer_render` → `kdj visualizer render` → `POST /api/visualizer/render`）：服务端的导出器用歌曲内嵌封面和默认场景
  出整首的 MP4（30 fps，偶数宽高，320×180–2560×1440，仅 macOS/Windows）。它是可视化的基础样式，不是用户在编辑器里调过的样子：
  编辑器的场景存在窗口的 IndexedDB / localStorage 里，服务端读不到。
- **报告**：做完用 tell_user（不自动消失）；AI 抽屉的「任务」页把消息全文写在步骤下面。
- **读网页**：web-search.json 的拒绝列表去掉 `::1`（pi-web-access 自己会拒绝回环和内网地址）。
- **YouTube**：已登录、视频可播却没有 HLS 清单的观看页，隔 0.8 秒、2 秒再要两次（yt-dlp #17143 记录过这种时有时无）。

## 第二次：同一首歌反复对齐（2026-10-19 晚）

会话 `2026-10-19T14-57-44-678Z_….jsonl`（deepseek-flash，推理「高」）：用户拖来《花ハ踊レヤいろはにほ》的 ミツキヨ Remix 和
NCOP，要主歌、副歌用 NCOP 对上 remix，其余用干净的动画剪影或图片填。62 次调用里约一半白做，交方案前就用了 40 次（技能写的是 8 次）。

| 问题 | 根子 | 改成 |
|---|---|---|
| 第一次 `kdj_align` 就给了两套方案（NCOP 20–78 → 37.4 秒起，副歌 50–78 → 229.4 秒起），它又把歌切成 0–40、110–200… 六段、把 NCOP 变调变速，前后对了 11 次去找段落；短片段对不上，它就把第二套当误报扔了 | 技能只说「先对齐」，没说对一次就是结论；探索的 8 次里 B 站候选的对齐不计数 | 每个素材只对一次（下载后本地再对一次），不截歌、不变调变速、不换参考；工具拒绝工作目录里的文件；只有每个候选那一次对齐不计数 |
| 写 env.py、scan.py 算能量和相关，又重跑上一次会话留下的脚本 | 「自己写脚本测出来的结果只用来核对」等于允许写脚本；这首没有小节线，没写该怎么办 | 不写脚本分析音频；没有小节线就用 bpm 和 segments 推，方案里写明是推的 |
| 读了工作目录里上一次任务的 gen.py、map.py | 工作目录跨会话共用，没说旧文件怎么对待 | 以前任务留下的文件，用户没提到就不读、不沿用 |
| 把「剪影」当关键词去搜绿幕、通用剪影素材，被用户打断 | 用户的说法有几种理解，它自己挑了一种 | 素材或画面的说法有几种理解时，先在方案里问 |

同时把散在代码里的工具说明全部搬进 `prompts/tools.md`，系统提示的各段也进了 `prompts/`，人能在一处看到模型收到的每一句话。

2026-10-20 删掉了 `references/ffmpeg.md` 和 `references/remotion.md`：滤镜配方和组件示例教不会本来不懂 FFmpeg、Remotion 的模型，
懂的模型又用不着，而且怎么列也列不全。FFmpeg 和 Remotion 怎么写交给模型自己；SKILL.md「做工程」只留 KDJ 自己的要求
（片段和画布同尺寸同帧率、不透明用 H.264 `.mp4`、透明叠层用 ProRes 4444 `.mov`、过渡片段盖在上一层、不带声音、和底下逐帧接得上），
工具的用法在 `tools.md`。已装好的数据目录里的这两份由 `write_extension` 删掉。

## 还没做的

- **.kdjv 的波形、BPM、调性**：现在工程被排除在分析之外（`kdj-library/src/service.rs` 的 7 处 `NOT IN (…'kdjv')`、`rhythm.rs:77`、
  `routes.rs` 的 `library_waveform` 400）。做法：分析和波形对工程行改为解码它的渲染（`kdjv::rendered`）或只渲染音频混音
  （`render.rs` 的 `mix_file`）；没有渲染时留在待分析而不是写错误；`write_analysis_tags` 跳过工程。要注意渲染记录只在内存里、
  缓存超过 2 GB 会清，素材变了而 .kdjv 没变时旧分析会留着。需要真机验证，单独做。
- **用编辑器里调好的可视化**：要让窗口把场景和图片同步给服务端（一个写进数据目录的接口），服务端渲染器也要补上编辑器的样式层。
- **YouTube 的真正兜底**：Safari HLS 正在被 YouTube 收走（yt-dlp PR #17261）。需要不要 PO token 的客户端（tv 等）的自适应格式，
  视频 + 音频用 FFmpeg 合流（和 B 站一样），没有 FFmpeg 的平台退回单文件 MP4。
- **Agent Mode 里的「做法」键**：先靠用户的话和方案第一题；要不要加一个像推理强度那样的键，等用过再定（视觉改动一次一处）。
