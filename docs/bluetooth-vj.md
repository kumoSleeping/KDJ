# 蓝牙连接与现场投放

KDJ 通过经典蓝牙 RFCOMM 传输连续音频识别特征，不传录音、歌曲文件或视频。音频发送端不播放声音、不创建 VJ 输出窗口，也不修改 DJ 软件的主输出或耳机预听路由。

## 连接与发送分开

1. 接收电脑选择「实时 VJ」，将「音频来源」设为「蓝牙接收」，选择演出后开始运行。只有这个来源会启动蓝牙监听；「自动」和具体本机设备均只采集本机，没有蓝牙接管或自动回退。
2. DJ 电脑进入「音频发送」。打开面板会读取系统已添加的设备；也可以点击「扫描设备」查找新设备。新设备通过「系统配对」打开 Windows/macOS 蓝牙设置完成配对和数字确认，回到 KDJ 后刷新已添加设备。KDJ 不保管配对密钥，也不静默确认配对。
3. 先选择目标并点击「连接」，等待 **KDJ 服务握手完成**。系统已配对不等于 KDJ 已连接。可以为多台电脑建立待命连接；应用最多保留 8 个连接，实际数量受蓝牙适配器和系统限制。
4. 接收端从已连接的 DJ 列表中点击「设为当前 DJ」。其他设备保持待命，不能抢占当前画面。
5. 当前 DJ 的发送端选择实际 Master 音频来源及声道，再点击「开始发送」。未连接或未被接收端指定为当前 DJ，均不能开始发送。
6. 「停止」结束音频发送，但保留连接及心跳。「断开」才释放该设备连接。接收端结束当前 DJ 或切换 DJ，会撤销原发送端的发送权限并停止其采集。

断线会停止采集，并以 2–30 秒退避尝试重新连接。重连后只恢复待命状态，不恢复当前 DJ 身份，也不自动录音或发送。接收端蓝牙监听故障也会重试；更换音频来源需先停止 VJ。停止 VJ 会释放其接收监听及连接，但不关闭已经开启的屏幕投放。

运行期间不进行主动蓝牙扫描，以免额外争用射频；仍可查看系统已添加设备。

## 默认画面与屏幕投放

- 在实时 VJ 面板的「默认画面」选择图片或视频，配置会保存。视频静音循环，图片保持显示；没有配置时保持黑色，不加入提示文案。
- 「开启投放」可在尚未开始识别时提前占住目标屏幕。图片与视频只使用系统解码，文件访问范围仅授权已选择的素材，不开放整个本机文件系统。
- 当前 DJ 尚未发送、结束、断线，或 VJ 停止时，显示默认画面。临时识别不到歌曲时保留当前音乐画面，不因短暂失锁反复切回默认画面。
- 手动切换下一位 DJ 后先显示默认画面，直到其音乐匹配成功、视频画面准备完成，再接管屏幕。旧 DJ 延迟到达的数据不能越过新的接管授权。
- 同一屏幕上的下一场会复用现有投放窗口，不为了重启识别退出再进入全屏。只有「关闭投放」才主动收起窗口。
- 全屏投放不显示控制条、错误信息或设备状态；错误留在操作电脑的主面板。默认素材更换时先准备新素材，失败则保留原有默认画面并报告错误。

## 音频与同步边界

Windows ASIO 独占输出未必能被系统回环捕获。外部混音时，电脑也未必具有最终 Master。请选择实际能得到 Master 的系统回环、硬件 Loopback 或调音台回传输入，并排除 Cue 声道。Windows 的「第二路 Master」接入方式保留为本机采集选项，需由 DJ 软件提供额外主输出，KDJ 不自动改路由。

特征有效载荷约 7.2 KB/s，协议头、确认与心跳另计。接收端复用现有 550 ms 查询窗口、声学匹配和共享视频调度。时间同步使用单调时钟四时间戳及滚动低 RTT 样本；界面上的时钟不确定度并不是实测大屏延迟。

每次 DJ 接管都有独立授权标识，采集流另有连续帧序号与采集代次。发送历史、待发送队列和未确认消息均有上限。数据过期、缺帧或时钟不连续时重新积累证据，严重积压时断开重连，不无限排队。

RFCOMM 使用可靠有序传输，干扰仍可能引起重传和队头阻塞；时间校准无法预知 Cue、Loop 回绕和突然切歌，也不会自动测出声卡、音响和大屏的延迟。多设备待命、系统授权、休眠恢复及长时间现场负载仍需在实际 Windows/macOS 电脑上验收，不能仅凭编译通过保证演出稳定性。
