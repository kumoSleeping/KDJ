# 旧 VJ 定位优化方案（待统一实施）

本轮只实施新实时 VJ 面板及其独立会话；旧混接编辑器不改匹配算法、阈值、持久项目或已有缓存格式。之前补充的计时日志继续保留。本文是供开发讨论的方案，不表示优化已经完成。

## 实测依据

见 `vj-alignment-performance.md`：同一视频与两段录音，全冷 14.427 秒；参考特征已有、新视频首次分析 5.254 秒；全部特征已有仍需 4.320 秒。开发构建，四种条件各一次，不能等同于发布版或大素材库指标。

| 优先级 | 改进 | 实测或代码依据 | 预期作用与风险 | 验证方式 |
|---|---|---|---|---|
| 1 | 模糊轮复用严格轮结论 | 同一对音频块在第二轮再次执行严格匹配，本样本重复约 618.551 ms | 去掉确定性重复计算；必须保留严格失败原因、取消检查和短版复核路径 | 原有 alignment 检查，同素材冷/热复测；候选、分段、速度和失败原因一致 |
| 2 | 变速候选扫描改成连续内存访问 | 模糊搜索的候选扫描占 1906.839 ms，矩阵生成仅 70.038 ms | 尝试交换循环顺序、重用工作区，让 CPU 批量处理相邻候选；不减少速度范围和候选数量 | 保持每候选累加顺序或检查数值误差；原有模糊/短版/歧义检查及真实素材对照 |
| 3 | 独立 PCM 转换移至优化的分析层 | 开发构建的 s16le→f32 花费 649.144 ms | 消除服务层未优化热循环；不改变缩放、字节序、输出样本 | 现有解码检查与实际特征/定位对照；分别报告 dev/release 收益 |
| 4 | 参考音频特征提前准备并稳定复用 | 冷轮解码共 8.015 秒，其中参考音频是主体 | 在空闲期按录音指纹预建索引，而非首次拖视频才准备；播放高负载时可让步、暂停、取消 | 检查首次导入、已有缓存、素材改写、变速编辑、缓存损坏恢复；不得影响音频播放 |
| 5 | 缓存序列化与摘要读取批量化 | 逐浮点 read_exact/write_all；9 块写入约 247.774 ms | 批量字节转换，避免重复文件打开；仍检查版本、长度、有限值及内存上限 | 运行已有缓存检查，读老缓存与坏缓存实际行为；缓存缺失必须可重建 |
| 6 | 检查按完整源域检索的重复成本 | 已裁切时间线仍对整份录音建立对应 | 保留完整源域以免跨剪辑发明速度变化；只优化录音级对应复用，不直接裁掉检索上下文 | 同一录音多切片、交叉淡化、短尾、曲线变速场景的原有检查 |
| 7 | 新旧两条流程共享声学资产，不混用结果语义 | 实时会话需要短窗匹配，旧编辑器需要全局分段/歧义判定 | 以后可统一索引存储、内存预算、签名与失效机制；实时的局部命中绝不能冒充旧编辑器完整定位 | 分别比较资产复用率和两种输出，确保数据目录与项目持久化安全 |
| 8 | 多级索引与增量查询 | 当前候选检索仍按录音块扫描，规模增长后成本上升 | 研究时间锚点指纹倒排索引，先找候选，再沿用严格声学校验；不能仅按粗搜分数自动放置 | 真实素材库规模阶梯实测、重复副歌、无关曲、不同版本、重混及噪声输入 |

## 从新实时面板可复用的设计

- 素材身份与时间线编排分离。换序、改 Set 名称不重做音频特征；源文件改变必须失效。
- 单会话、可取消、固定内存预算。不能通过无限并发把墙钟时间降下来，却抢占 DJ 音频线程。
- 保留实际分阶段时间：准备素材、解码/特征、候选扫描、精细验证、输出首帧。不要把结果缓存命中当成新素材识别速度。
- 当前项与下一项优先，后台发现仍有固定份额。但这条实时调度策略不直接移植到旧编辑器：旧编辑器需要完整对应，不能漏掉后面的更优或冲突候选。
- 命中后跟踪位置；无证据不清空画面。此为实时输出策略，不改变旧项目剪辑结果。

## 新实时链路的验证边界

本轮在隔离数据目录、真实 macOS Tauri 窗口中验证了系统音频匹配视频、匹配音频后绘制歌词可视化、两者切换、独立窗口和当前屏幕全屏，以及输入停止后继续播放。Set 的曲库拖入、排序和重启读取也已验证；没有连接外接屏，未验证实际跨屏输出。

单视频场景曾显示约 10.9 ms/轮，这是单次界面观察值，不是端到端延迟或统计分位数。当前需要 8 秒证据窗及连续确认；素材索引准备、采集积累、计算和首帧等待必须分别测量。变速、重混、Windows 捕获和大 Set 压力场景尚未完成，不能由这一观察值推算它们的表现。

实时缓存目前独立，采用 8 kHz 分析、300 秒块和重叠区；以后与旧流程共享时，必须将采样、重叠、特征版本等参数纳入资产身份，不能直接把两个流程的缓存文件互换。

## 实施顺序与验收边界

先做 1–3 的等价计算优化，再做 4–5 的资产缓存优化，最后考虑 6–8 的检索结构。每组修改只运行已有的相关检查，不新增测试脚本或夹具；使用同一真实素材和隔离数据目录复测并清理临时产物。

验收同时看：墙钟耗时、CPU 时间、峰值工作集/缓存大小、取消响应、音频负载下的稳定性、匹配结果是否变化。任何降低准确度或缩窄检索范围的方案都须单独说明，不能混进等价性能优化。旧 `vj-projects.json` 不用于实验性写入。
