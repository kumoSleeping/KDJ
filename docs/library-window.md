# 万首曲库：按位置加载与悬浮滚动条

## 实现

本地曲库读取完整的有序 ID 清单，再按视口读取歌曲摘要。滚动条的长度和位置由完整清单决定，跳到末尾不会顺序加载前面的歌曲。旧的 `/api/library/tracks` 分页接口继续保留。

- `GET /api/library/tracks/index` 接收原有筛选、文件夹及主副排序参数，返回 `{ track_ids, total }`。不接受分页游标；排序、空值和同值顺序与原分页查询共用实现。
- 摘要每批最多 500 首（服务端上限），最多两个并发请求，当前视口优先；其中一个请求位在后台从视口向外补齐整份清单。内存保留最多 50000 首，超出后按 LRU 淘汰并保护当前预取范围。
- 查询版本隔离索引、摘要和错误；后台事件以 ID 回填，250 毫秒合并、最长等待 1 秒，不再排序和裁剪整个前端歌曲数组。请求 15 秒超时。失败或超时的批次不是终态：其中的行按 1、2、4、8、15 秒的间隔自动重新排队，期间保留错误提示和重试按钮，加载成功后提示自动清除；五次之后才停下，等待重试按钮、涉及这些行的后台事件，或视口再次需要它们。
- 全选、Shift 区间选择、键盘/MIDI 浏览、下一首播放、定位和批量操作使用完整顺序。详情独立于摘要缓存。
- 虚拟窗口和实际滚动位置同时限制在有效范围；后台变更保持顶部歌曲 ID 和行内偏移，切换查询回顶部。旧会话的像素位置仍可恢复。
- 滚轮、触控板和触摸滚动由 WebView 的滚动线程执行，页面不取消 wheel 事件。页面接管滚轮（拦下 wheel、在动画帧里改写位置）可以保证位置和行同帧画出，但滚动位置只能跟着主线程的帧前进：造行一慢，滚动本身就卡。反过来，交给滚动线程后页面拿到位置时它已经在屏幕上了，而一行真实的行是十几个单元格的 DOM，造一批要几毫秒到几十毫秒：快滚时无论提前造多少屏都会被追上，露出空白，主线程还被造行占满。所以快滚时不造行，改画替身行。
- 所有来源的滚动（滚动线程的，以及拖滑块、键盘、定位这些页面自己执行的）都走容器的 scroll 事件，一帧合并一次。滚动节奏由 `libraryScrollPace` 判定：速度按约 100 毫秒平滑（单次滚轮格不算快），超过 3 px/ms 进入快滚，降到 2 px/ms 以下退出；一帧走过两屏以上（拖滑块，或页面卡了一下）直接算快滚；140 毫秒没有新的滚动帧算停稳。
  - 阅读速度：在这一帧内用 `flushSync` 提交对应的行。渲染窗口为视口前后各两屏，按 8 行一步移动，一步之内的滚动帧不进 React。没有任何动画。
  - 快滚：表格的行原地不动，React 不参与滚动帧；只画替身行。慢下来（那一帧）或停稳时在当前位置一次造好真实的行，造好的行用一次到场动画追上滚动（见下面"行的到场"）。
- 替身行（`src/lib/libraryStandIns.ts`）是跟着表格滚动的 canvas，每块 24 行，位置固定在行号上，进入范围时画一次。canvas 是独立图层，滚动线程滚到时已经画好。要铺多远取决于速度：实测甩动一个 2000 首的列表是每秒 4 万到 9 万像素，页面一帧慢到 100 毫秒就是十几屏的路程。
  - 替身行只有灰条：每个文字的位置一条淡灰条，四分之一分辨率，不画文字。这个速度下什么也读不清；画一份"假的列表"只会在慢下来时被真的那份硬生生换掉。图样只画一次，一块就是一次 `drawImage`；视口内的块当帧画完，视口外的每帧最多 16 块。
  - 覆盖范围是视口后方一屏、前方六屏，再加视口前方半秒的路程（按当前速度，平滑速度和上一帧的瞬时速度取大），最多 64 块。
  - 每条灰条的位置、可用长度和颜色从一行真实的行量出来，所以跟随主题、列的顺序和宽度以及两行式布局；行高、列或主题变化后重新量，被要求重新量而结果没变时什么也不做。灰条和数据无关：摘要到达、换序、换调号记法都不重画。
  - 替身行按真实的行所在的范围裁掉，两者不重叠；表格自己造行时不保留任何画布（像素在最后一次显示之后保留 4 秒，接着的下一次甩动直接复用）。
  - 位置用表格摆放未渲染行的同一个行高，画布层的大小就是表格本身并裁掉超出的部分：画布不能让滚动范围变长。
  - 行追上来时（`settle()`），视口前后各一屏之内的画布带上 `data-leaving`，在到场的行上面用 110 毫秒淡出后释放，其余的立刻释放；淡出期间表格再要求"静止状态"不会动它们，又一次快滚则立刻结束淡出、重新铺灰条。减少动态效果时不淡出，直接释放。
  - 快滚途中表格不动，数据层不知道眼前是哪里；每走过 300 行把摘要的加载重心挪到眼前一次。
  - 量不到真实的行、或没有 canvas 时不启用，表格在任何速度下都自己造行（也就没有追上来的动画）。`localStorage["kd-library-standins"] = "off"` 可以关掉它用于手动对比（挂载时读取一次）。
- 快滚的那些帧里每帧做的事（`syncWindow` 的快滚分支）：读容器的位置和尺寸、算一次节奏、算一次替身行的铺设计划（几十块以内的纯计算）、给新进入范围的块各一次 `drawImage`（视口外最多 16 块）和几条样式写入；每 300 行向数据层要一次摘要。不进 React，不建 DOM 行，不调用 `fillText`，不量文字。
- 到顶或到底之后 WebView 的回弹会继续报出范围之外的滚动位置。那不算滚动：位置按可滚范围取值，到边后不再变化，表格和替身行都不动；页面也不把容器拉回去，只有 DOM 确实比列表长（列表变短而 DOM 还没跟上）时才写回。
- 行的到场（`components/library/listArrival.ts`、`ListArrival.css`，数值和关键帧在 `motion.css` 的"A list that is presented"）。表格只说哪些行、按什么先后；模块给滚动容器带上 `data-kd-arrive`（哪一种）和 `data-kd-arrive-from`（行从哪一侧来），给每一行带上 `data-kd-arrive-row` 和 `--kd-arrive-i`（第几拍），动画结束后全部去掉。行由表格自己的占位行定位，没有 transform，所以动画只动行自身的 opacity/transform，不改布局。
  - 列表被呈现（`list`）：应用启动后第一次显示、换成另一份（查询版本变化、滚动回到顶部的那一处）、以及所在板块重新显示（`visible` 属性由 false 变 true；板块切走只是 `display: none`）。视口里的行播放和搜索结果相同的动作：前十四行自上而下各隔 28 毫秒升起 14 像素并淡入，封面晚 70 毫秒缩放出现，其余的行在第十四行之后一帧淡入；914 毫秒内结束。在列表当时所在的位置播放，不限于顶部。离开到场时的位置超过 2 像素（任何滚动）立即结束。到场途中列表又被换掉（逐字输入筛选词）时，留下来的行继续原来的动作，只有新进入视口的行开始，不整屏重来。
  - 行追上滚动（`chase`）：只在快滚确实把行甩在了后面（那几帧没有造行）而慢下来或停稳时。视口里新造的行从滚动来的那一侧开始、顺着滚动的方向一行接一行到场（每行隔 8 毫秒，160 毫秒到位，封面晚 40 毫秒；向列表末尾滚时从下方升起，向顶部滚时从上方落下），前方一屏的行随最后一拍淡入；304 毫秒内结束。之前就在渲染窗口里的行不动——短促的一甩没有滚出已有的行，就没有动画。动画期间滚动的余势照常按阅读速度提交行；再次快滚立即结束。
  - 动画进行中摘要到达、占位行换成真实的行（React 重新挂载该行）：新行按原来的拍子加入，用负的延迟接上其它行已经走到的进度，不从头再来。
  - 滚动（阅读速度）、重渲染、选中、单行更新、虚拟窗口换行都不会加标记。减少动态效果时不加任何标记。Sakura98 主题包按同样的拍子逐行"打出来"，没有滑动。
- 行是记忆化的组件，交互处理函数的身份不变：窗口移动只渲染新进来的行，留在窗口里的行整行跳过。
- 数据在渲染前一屏开始请求。待下载行同样虚拟化。
- 开发版在每次走过三屏以上的滚动停稳后往原生日志写一条 `library-scroll`（`kdj_ui_trace`）：帧数、超过 50 毫秒的帧数、最长帧间隔、单帧最大位移、最高速度、不造行的帧数（`held`），"新视口里有行既没有真实的行也没有替身行"的帧数和最多缺的行数（`bare`、`bareMax`），以及画了多少块灰条、画它们一共和单帧最多花了多少毫秒（`bars`、`paintMs`、`paintMax`）。用户看到空白而 `bare` 为 0，说明空白不是页面没画，而是 WebView 没来得及把已有的内容显示出来。
- 封面保留四个并发请求及 512 张缓存目标；取消的任务不能再被复用，旧任务不能清掉同键的新任务。网络/服务端临时失败最多重试两次，404 音频封面不轮询。可视范围内的请求优先；窗口移动后由表格统一调整等待中请求的优先级，行不为此重渲染。行挂载时先同步读取已有结论：缓存里有封面就直接画，已知没有封面就直接画唱盘，未知时格子留空，不再先画唱盘再换成封面；“没有封面”只是首帧提示，每次挂载仍会向服务端确认。

## 滚动条

曲库使用独立悬浮滑块，原生轨道隐藏，不为轨道留出布局空间。横向位于底边，纵向位于右边；滑块贴边、常驻可见，默认 6 像素，悬停及拖动时 8 像素，透明命中范围为 14 像素。最短滑块 44 像素。

仅滑块响应拖动，轨道区域不拦截歌曲交互；滚轮、触控板和触摸继续走原滚动容器。滑块支持方向键、Home/End、PageUp/PageDown、焦点样式及减少动态效果设置。滑块位置直接更新 DOM，不通过 React 每帧重绘表格。

## 自动验证

- `npm run test:library`：请求竞态、超时与重试、远跳、缓存上限、封面取消与重试、滚动条几何，以及真实 React 表格和状态模块的 JSDOM 测试。
- `npm run typecheck`。
- `cargo test -p kdj-library --lib library_index_`：完整索引与分页在主副排序/筛选下顺序一致，以及一万条数据库记录的直接末尾摘要查询。
- `cargo check -p kdj-server --lib`。

桌面 CI 已接入前端定向回归。测试使用内存数据或内存数据库，不生成歌曲、截图或临时项目。

## 玩家实机验收

自动验证不代表 Tauri 帧率达标。此变更尚未记录真实 Tauri 的修改前后帧率；本项保持待验收。

后端已修改，实机检查前需完整重启 Tauri 开发会话。检查同一万首文件夹：

1. 滚轮/触控板连续快滚（含惯性）、拖竖向滑块到末尾、横向拖到最后一列，再分别返回。滚动手感（惯性、到边停止）应与发行版一致，不随主线程忙闲变化。快滚途中表格主体应始终有灰条（替身行），不露白；慢下来或停稳后真实的行从滚动来的那一侧依次追上来、灰条同时淡出，行的位置不应跳动；慢慢滚动时不应出现任何动画。到顶、到底后继续滚不应闪动；刚启动、摘要还在分批到达时快滚也不应闪动。
2. 在末尾切换文件夹、搜索和排序；确认回到顶部，无巨大空白占位。
3. 开启后台分析时滚动；确认更新不截断列表，正在看的歌曲保持位置。
4. 分别在冷/热封面缓存下往返滚动；检查文字先显示，封面能够恢复。
5. 跨未缓存区域 Shift 选择、全选、MIDI 步进、下一首及定位正在播放。
6. 关闭后恢复到深位置，并调整窗口、字号及列宽。
7. 滚动途中重启后端或断开本地服务：错误提示出现后不点重试，确认服务恢复后占位行在数秒内自行加载、提示消失。

性能目标：热缓存滚动不产生由列表代码引起的超过 50 毫秒主线程长任务；目标摘要到达后两帧内显示。实测时记录机器、Tauri 构建模式、窗口尺寸、刷新率、分析状态和缓存状态；未测量前不宣称达到该目标。
