# 万首曲库：按位置加载与悬浮滚动条

## 实现

本地曲库读取完整的有序 ID 清单，再按视口读取歌曲摘要。滚动条的长度和位置由完整清单决定，跳到末尾不会顺序加载前面的歌曲。旧的 `/api/library/tracks` 分页接口继续保留。

- `GET /api/library/tracks/index` 接收原有筛选、文件夹及主副排序参数，返回 `{ track_ids, total }`。不接受分页游标；排序、空值和同值顺序与原分页查询共用实现。
- 摘要每批最多 500 首（服务端上限），最多两个并发请求，当前视口优先；其中一个请求位在后台从视口向外补齐整份清单。内存保留最多 50000 首，超出后按 LRU 淘汰并保护当前预取范围。
- 查询版本隔离索引、摘要和错误；后台事件以 ID 回填，250 毫秒合并、最长等待 1 秒，不再排序和裁剪整个前端歌曲数组。请求 15 秒超时。失败或超时的批次不是终态：其中的行按 1、2、4、8、15 秒的间隔自动重新排队，期间保留错误提示和重试按钮，加载成功后提示自动清除；五次之后才停下，等待重试按钮、涉及这些行的后台事件，或视口再次需要它们。
- 全选、Shift 区间选择、键盘/MIDI 浏览、下一首播放、定位和批量操作使用完整顺序。详情独立于摘要缓存。
- 虚拟窗口和实际滚动位置同时限制在有效范围；后台变更保持顶部歌曲 ID 和行内偏移，切换查询回顶部。旧会话的像素位置仍可恢复。
- 列表是行列表（`docs/row-list.md`）：行是文档流里的 grid，不定位，没建出来的行由 body 的 padding 代替，由 `@tanstack/react-virtual` 决定建哪些（`src/components/common/rowList.ts`）。不是 `<table>`：表格的行插入会让整表重排，行上的动画又合成不了；也不是绝对定位的块：每个定位元素都是 WebKit 的一个层，两千个层让每次滚动都要遍历两千个层（2026-10-12 的滚动日志：JS 每帧一两毫秒，主线程却每帧 50 到 180 毫秒）。
- 节奏跟着 WebKit 的瓦片走，不跟帧走。三千首以内的列表整体挂载：先挂视口附近的窗口，再每隔一帧挂 250 行；之后滚动时 DOM 零改动。更长的列表保留视口前后各三屏，滚过整整一屏才挪一次窗口，不用 flushSync，挂卸行的位置离视口两三屏。滚动帧里不渲染、不量布局、不切祖先属性。
- WebKit 里（macOS、Linux 的 WebView）曲库自己滚：页面接滚轮、写 `scrollTop`，只保留视口前后各半屏的行，每个 scroll 事件里把进出窗口的行渲染好；一次进来太多行时先只有序号，随后填内容。原因和做法见 `docs/row-list.md` 的"WebKit 里曲库自己滚"。上一条的整体挂载和三屏窗口是其它引擎的。
- 其它引擎里滚轮、触控板和触摸滚动由 WebView 的滚动线程执行，页面不取消 wheel 事件；拖滑块、键盘、定位这些页面自己执行的滚动同样只走容器的 scroll 事件。
- 到顶或到底之后 WebView 的回弹会继续报出范围之外的滚动位置。那不算滚动：虚拟化器按可滚范围取行，页面不把容器拉回去。
- 停稳（150 毫秒没有新的滚动帧）时记下顶部的行和行内偏移：后台换索引时按它保持位置，持久会话也记下它；板块被 `display: none` 隐藏后重新显示时按它放回。
- 行的到场（`src/components/common/listArrival.ts`、`ListArrival.css`，数值和关键帧在 `motion.css` 的 "A list that is presented"）。标记只在行上：`data-kd-arrive`（哪一种）、`data-kd-arrive-row`（第几拍的 step，还是跟最后一拍一起的 rest）、`data-kd-arrive-from`（行从哪一侧来）、`--kd-arrive-i`（第几拍）、晚加入的行带 `--kd-arrive-lag`；动画结束后全部去掉。不在祖先上放任何标记，所以标一行只让这一行的样式失效。行由 `top` 定位、没有 transform，动画只动行自身的 opacity/transform，由合成器执行。
  - 列表被呈现（`list`）：应用启动后第一次显示、换成另一份（查询版本变化、滚动回到顶部的那一处）、以及所在板块重新显示。视口里的行播放和搜索结果相同的动作：前十四行自上而下各隔 28 毫秒升起 14 像素并淡入，封面晚 70 毫秒缩放出现，其余的行在第十四行之后一帧淡入；914 毫秒内结束。在列表当时所在的位置播放，不限于顶部；位置由表格写入后，等虚拟化器为那个位置渲染出行（最多等 400 毫秒）再开始。离开到场时的位置超过 2 像素立即结束。到场途中列表又被换掉时，留下来的行继续原来的动作，只有新进入视口的行开始。还没载入摘要的行照样到场，摘要到了在同一个元素里换上内容，行不重挂。
  - 行追上滚动（`chase`）：阅读速度的滚动在视口外就把行备好，不会有动画；一次甩动跑在造行的帧前面时，视口里的位置先露出来、行后到，这样的行按它离来向那一边的距离接上同一个时钟（每行隔 8 毫秒，160 毫秒到位，封面晚 40 毫秒；向末尾滚从下方升起、顶上的先到，向顶部滚从上方落下、底下的先到），所以隔一帧才造出的行也一行接一行到场，而不是一帧一坨；来不及赶上自己那一拍的行直接就位。一个时钟 304 毫秒后结束，下一批晚到的行另起一个。建过一次的行再回来时直接就位，不重播（记住最多五万行）。
  - 减少动态效果时不加任何标记。Sakura98 主题包按同样的拍子逐行"打出来"，没有滑动。
- 行是记忆化的组件，交互处理函数的身份不变：视口移动只渲染新进来的行，留在视口附近的行整行跳过。
- 数据在渲染前一屏开始请求（`libraryDemand`）。待下载行同样虚拟化。
- 同一份日志里还有在线曲波形的 `stream-waveform`（`src/lib/streamWaveformTrace.ts`，同样只在开发版）：每首歌几行，记录服务端报告的 `status`、`complete`、`active`、`revision`、`covered`（已解码秒数）、`bytes`（已缓存/总字节）、底栏用的时长 `bar`、波形实际铺开的时长 `rail`、容器声明的时长 `probed`，以及 `place`：`full`（完成的波形铺满整条）、`prefix`（只盖住前 `covered` 秒）、`kept-finished`（保留已有的完整波形，没有换成新一轮的前缀）、`none`。波形只占前半时看这一行：`partial` 且 `covered` 小于 `bar` 是还在加载；`ready` 却仍是 `prefix` 是解码比曲目短且没有旁证。
- 封面是普通的 `<img>`，直连缩略图路由（`private, max-age=3600`），由浏览器自己的图片管线请求、解码和缓存；没有页面侧的队列和 blob。行在视口外两三屏就挂好，图片进入视口时已经在了，所以不用 lazy。浏览器显示过的封面记在模块里，行重建时同步解码、不闪；没有封面的音频也记着，再次挂载时第一帧就是唱盘；视频首帧由后端抽取，服务短暂重启或抽帧排队时换个地址每 3 秒再试，最多 12 次。

## 滚动条

曲库使用独立悬浮滑块，原生轨道隐藏，不为轨道留出布局空间。横向位于底边，纵向位于右边；滑块贴边、常驻可见，默认 6 像素，悬停及拖动时 8 像素，透明命中范围为 14 像素。最短滑块 44 像素。

仅滑块响应拖动，轨道区域不拦截歌曲交互；滚轮、触控板和触摸继续走原滚动容器。滑块支持方向键、Home/End、PageUp/PageDown、焦点样式及减少动态效果设置。滑块位置直接更新 DOM，不通过 React 每帧重绘表格。

## 自动验证

- `npm run test:library`：请求竞态、超时与重试、远跳、缓存上限、滚动条几何、行的到场，以及真实 React 行列表和状态模块的 JSDOM 测试（`tests/libraryTable.test.tsx`、`tests/resultTable.test.tsx`）。
- `npm run typecheck`。
- `cargo test -p kdj-library --lib library_index_`：完整索引与分页在主副排序/筛选下顺序一致，以及一万条数据库记录的直接末尾摘要查询。
- `cargo check -p kdj-server --lib`。

桌面 CI 已接入前端定向回归。测试使用内存数据或内存数据库，不生成歌曲、截图或临时项目。

## 玩家实机验收

自动验证不代表 Tauri 帧率达标。此变更尚未记录真实 Tauri 的修改前后帧率；本项保持待验收。

后端已修改，实机检查前需完整重启 Tauri 开发会话。检查同一万首文件夹：

1. 滚轮/触控板连续快滚（含惯性）、拖竖向滑块到末尾、横向拖到最后一列，再分别返回。滚动手感（惯性、到边停止）应与发行版一致，不随主线程忙闲变化；起步和落地不应有卡顿。甩动途中露出的只能是面板底色（没有假内容），行从滚动来的那一侧一行接一行追上来，行的位置不应跳动；慢慢滚动时不应出现任何动画。到顶、到底后继续滚不应闪动；刚启动、摘要还在分批到达时快滚也不应闪动。
2. 在末尾切换文件夹、搜索和排序；确认回到顶部，无巨大空白占位。
3. 开启后台分析时滚动；确认更新不截断列表，正在看的歌曲保持位置。
4. 分别在冷/热封面缓存下往返滚动；检查文字先显示，封面能够恢复。
5. 跨未缓存区域 Shift 选择、全选、MIDI 步进、下一首及定位正在播放。
6. 关闭后恢复到深位置，并调整窗口、字号及列宽。
7. 滚动途中重启后端或断开本地服务：错误提示出现后不点重试，确认服务恢复后占位行在数秒内自行加载、提示消失。

性能目标：热缓存滚动不产生由列表代码引起的超过 50 毫秒主线程长任务；目标摘要到达后两帧内显示。实测时记录机器、Tauri 构建模式、窗口尺寸、刷新率、分析状态和缓存状态；未测量前不宣称达到该目标。
