# 工作站与 BPM V4

实现日期：2026-09-07。桌面运行时仍为 Rust + Tauri；没有新增模型、模型下载、Python 运行时或媒体解码依赖。

## 使用与兼容

入口为「工作站」和剪刀图标。音乐直接在现有素材轨道上剪辑，复用 `release-overview` 预览波形缓存；不再挂载独立细节波形、额外波形解码或 BPM 分段按钮列表。音频轨道放大为带留白的半幅波形，显示按源时间映射的剪切、变速与空隙。

「小节吸附」默认开启，与原有时间轴边界吸附独立。定位、片段入出点及移动使用屏幕距离容差吸附，Alt 拖动临时关闭；剪断操作落在选中片段内最近的小节首拍。裁剪延长仍可吸附保留的源素材拍点，纯音频不先量化到视频帧。波形、拍线与剪辑共用源时间映射；缩小时拍线和编号按像素间隔稀疏显示，吸附仍使用完整拍点。删除、接合、复制、淡化、撤销重做沿用视频素材的操作。

每个有声音的源素材共享一次全曲精确 BPM 分析，已有普通结果会升级为精确模式，失败或取消不自动反复重试。轨道上标记必要的 BPM 变化，工具区提供「BPM 分析」和选中片段的小节数；首拍证据不足时明确显示「首拍置信度低」。既有且源签名有效的人工网格优先使用，重分析不覆盖它或既有剪切点。小节吸附保证的是落在当前网格上，不等于保证自动识别正确或任意首尾接合听感自然。

新增和复制轨道向下追加，导入顺序与输入相同；旧工程顺序与顶部画面覆盖底部画面的规则保持不变。音视频仍共用同一片段映射。纯音频新工程默认 WAV；旧工程缺省格式解释为 MP4。输出设置还提供 FLAC、320 kbps MP3 和 MP4，含视频工程也能只导出音频。

音频输出复用 48 kHz、双声道、16 位混音，跳过视频渲染与视频流校验。真实接点使用最多 2 毫秒短淡变去点击，不叠加片段、不改变时长；连续源片段的纯切分不添加音量下陷。完成后检查流类型、时长和全程可解码性，沿用取消、清理、同名避让及成品入库。

## 分析与数据

`kdj-analysis::rhythm` 流式解码整曲为 22,050 Hz 单声道，仅保留解码包和重采样上下文，不常驻整曲 PCM。2048 点频谱窗、220 样本步长、64 个 Mel 频带产生起音与低频重音特征；短时能量攻击点用于拍点时间定位，避免长频谱窗提前响应造成系统时间偏差。

局部自相关候选结合拍上／细分周期证据和低频重音评分，使用动态规划选择随时间变化的速度路径，再跟踪拍点。默认每四秒取重叠上下文，精确模式每两秒取样并增加候选；候选冲突扩大搜索，弱区域扩大上下文，全部复用首次解码的特征。步长缩短时按时间缩放路径得分，避免精确模式仅因窗口翻倍就更容易跳到另一节奏层级。

分段按拍点间隔与相位误差扩展，再在误差约束下合并。渐变保留实际拍点；静音不填造拍点。完整跟踪及分段没有 256 段或其他产品数量上限。算法参考传统组成：[Essentia Percival](https://essentia.upf.edu/reference/std_PercivalBpmEstimator.html) 的相关性速度估计，以及 [librosa beat_track](https://librosa.org/doc/main/api/generated/librosa.beat.beat_track.html) 的起音／速度／动态规划流程。本项目采用现有 Rust DSP 自行实现，未嵌入这些项目的运行时或模型。

`track_rhythm_v4` 独立存储签名、算法修订、精确模式标识、标量摘要与完整事件结果。曲库摘要只查标量；详情和节奏接口按需读取数组。旧节奏、调性和响度结果保留，V4 仅在完整成功后替换有效节奏数据；不会自动升级整库。清理基础分析缓存包括 V4。工作站保存轨道网格、分析修订与源签名，复用工程 revision 冲突检查。

新增 `GET/POST /api/library/rhythm/{id}`，分析入口也接受 `version: "v4"` 和 `precise`。后台复用分析注册、任务准入、取消和去重，编辑素材使用优先通道。曲库右键提供 BPM V4 分析；工作站自动分析及「BPM 分析」重试均请求整曲精确模式。

- 本地媒体回归覆盖 WAV／FLAC／MP3 实际导出、区间时长、追加顺序、连续／非连续剪切接缝、音视频变速、画面叠加、取消清理及旧工程迁移。两项需要显式指定工程日志的个人素材专项测试，因没有提供该日志，未执行其验收内容。

复现与标注评测：

```sh
cargo run --release -p kdj-analysis --example rhythm_bench
cargo run --release -p kdj-analysis --example rhythm_bench -- /path/to/song.wav --precise --truth=/path/to/annotation.json
```

标注 JSON 使用秒，字段为 `beats`、`downbeats` 和 `segments`；每段包含 `start_seconds`、`end_seconds`、`bpm`。评测报告拍点／首拍 F1（70 ms 一对一匹配）、匹配点 P95、首尾漂移、变速边界匹配（500 ms），以及误差不超过 0.1 BPM 的标注时长比例。BPM 不使用半速／倍速容错，遗漏覆盖会降低得分。没有标注时 `evaluation` 为 null。
