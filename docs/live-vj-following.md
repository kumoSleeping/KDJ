# 实时 VJ：先跳转，再跟随

## 跳转

底层声学算法和判定阈值保持不变，以 `matched || supported` 为唯一接受条件：通过就发布位置。删除上层额外的 0.66 / 0.54 / 0.14 门槛、跨候选二次否决和连续确认等待。检索召回但未通过声学校验的位置，不算识别成功。

局部识别通过时直接跟随，不再定时重复全 Set 搜索。失锁后先按当前速度检索，再由近到远尝试 0.80–1.25× 的速度档；每档校验后立即采用首个通过结果，不等待剩余速度或素材校验。

保留固定 550 ms 音频窗，不因歧义自动延长到 900 ms。未命中时，每批检索在完成当前速度档后检查 125 ms 调度预算；到点就用下一批新音频继续剩余速度档，不从头反复扫。这是档间让出执行的软预算，不是单档耗时或端到端切入延迟的保证，也不增加后台审计线程。

已确认位置交给共享 `VideoSeekQueue`。WebKit 备用视频保持音乐基准速度，使用实际出帧误差估计解码提前量，最多尝试三次定位；确认连续出帧且误差不超过 80 ms 后，才以 160 ms 叠化切入。其他解码器仍等待目标位置的新解码帧，不只看 `currentTime` 或 `seeked`。新的跳转、速度或暂停状态变化取消旧准备任务。超时或失败保留原画面，重试从 5 秒逐步退避到 60 秒，不连续冲击解码器。

这只代表视频定位已完成，不代表已经测得精确的上屏同步。细小相位误差交给切入后的跟随处理。

## 设备与入口

右上角「视频工具」统一提供剪辑、实时 VJ、可视化视频三个入口。实时 VJ 打开后即列出声音输入和画面输出，选择后一次开始；枚举设备不会提前录音。

实时 VJ 与音频发送共用音频来源分组：「输出设备捕获」「系统混音」「录音输入」。Windows 的输出设备列表包含默认播放设备和各个 WASAPI 回环端点；Windows 和 Linux 的「自动」仍使用系统默认录音输入。指定设备断开时报告错误，不静默改用其他麦克风。

macOS 14.2 及以上新增 Core Audio Tap：选取指定输出设备的音频流，关闭单声道／立体声混音，再从原始声道中选取相邻声道对。它不要求该硬件提供录音输入，也不安装虚拟声卡驱动；只在开始时创建私有 Tap 与输入聚合设备，停止或启动失败时销毁，不修改默认播放设备或使 DJ 输出静音。多音频流的设备按「音频流 1、2…」分别列出，CH 编号相对于所选流。设备或流格式发生改变时停止读取并报告错误，不在运行中换设备。

Mac「自动」优先推荐正在使用的有线外接音频设备，其次是系统默认输出；前端开始时固定到已显示的设备。该推荐不识别 DJ 软件，也不保证 CH 1/2 就是 Master。Tap 可用时遇到权限、设备或格式错误，不自动退回系统混音。旧系统不支持 Tap 时，「自动」仍使用原路径；所有系统均保留可手动选择的「系统混音 · ScreenCaptureKit」，以及原生声卡／麦克风输入。Tap 与 ScreenCaptureKit 均需要系统音频录制授权，枚举列表不会请求录音。

输入声道按设备当前原生 / 共享配置提供 `CH 1/2`、`CH 3/4` 等相邻声道对；单声道或奇数末声道单独列出。默认选择前两个声道（单声道设备使用 CH 1），这是通用默认值，并不保证对应每台混音台的 Master。手动选择在本面板内切换设备、刷新和重新开始时保留；设备声道减少导致所选声道不可用时阻止启动，不静默换到别的声道。识别与电平只使用所选声道：当 Master 与 Cue 保留在不同声道时，不主动把另一对声道混入；上游已经混合的两路声音无法再分开。ScreenCaptureKit 只显示 L/R，不能将其理解成硬件的 CH 1/2，更不能据此认定预听已隔离。

Windows 回环不是 ASIO 或 WASAPI 独占输出捕获，也不能监听另一块声卡上的播放。DJ 软件走 ASIO / 独占输出时，应选择声卡提供的回送输入，或把实际音频接入一个可被 WASAPI 读取的输入设备。更换设备或系统默认设备后，停止、刷新设备并重新开始。设备枚举不会录音；开始后，诊断中的来源、采样率、声道电平和音频包数可用来确认是否接收到正确音源。

画面「自动」在开始时重新检查显示器：macOS / Windows 优先外接设备，否则使用本机独立小窗。外接识别接口失败（例如 Windows 远程会话）时记录警告并使用小窗，不阻断手动选择输出。Linux 使用显示接口名称识别内置屏，单个无法识别的显示器保留小窗。

素材导入仍需现有媒体工具中的 `ffprobe`；缺失时由原有媒体工具安装入口补齐。视频由系统 WebView 解码，Windows 使用 WebView2；并不保证所有 MKV、MOV 或 HEVC 素材都能直接播放。上述 Windows 路径尚需真机验收，macOS 的编译检查不代表 Windows 采集及解码已通过。Core Audio Tap 的实际 Master／Cue 隔离也必须按具体 DJ 软件和声卡路由验证：先确认主输出能被采集，再令软件 Master 静音、只开耳机 Cue，检查运行中的实时采集电平是否保持静音；不要用停止后残留的电平判断。

WASAPI 捕获标志：KDJ 使用打补丁的 CPAL 0.18.1（`vendor/cpal-0.18.1`，说明见其中 `KDJ-PATCH.md`）。`AUDCLNT_BUFFERFLAGS_SILENT` 包按同长度静音交给回调，不读取引擎缓冲区中的旧内容；两种标志都不停止采集：`DATA_DISCONTINUITY` 作为不连续事件丢弃当前识别窗口、开始新的采集代次、计入诊断中的「断流」次数，并在诊断日志中记警告（最多每 5 秒一条，附带累计次数）；`TIMESTAMP_ERROR` 只表示该包的采集时间不可靠，音频本身仍连续，因此该包接在上一包之后继续使用，不清空识别窗口，只有在尚无可续接的时间线时才丢弃。不会因此切换设备或声道。回环仍仅作为显式选项接入，不替换 Windows 默认输入；补丁尚需真机验证静音恢复、默认设备切换和热拔插后，才能视为通过演出稳定性验收。

## Windows：VDJ / Inpulse 500 的第二路 Master

当 VDJ 使用 500 的 ASIO 输出、KDJ 无法直接回环时，可让 VDJ 另外把 Master 送到电脑已有声卡的 WASAPI 共享输出。无需虚拟声卡、插件或本地广播服务；不是从 ASIO 驱动中截取声音。

1. 在 KDJ 的实时 VJ 或音频发送界面，将「接入方式」切换为「第二路 Master · 电脑声卡」。
2. 手动选择具体的电脑播放设备及声道对。这个入口不使用「自动」或「默认播放设备」，防止系统默认设备改变后捕获另一条路线；它也不会猜测哪台设备就是电脑扬声器。
3. 在 VDJ「设置 → 音频」保留原有 `master → Inpulse 500 ASIO → OUT 1 & 2` 和 `headphones → Inpulse 500 ASIO → OUT 3 & 4`。
4. 在 Outputs 点 `+`，新增 `master → 上一步选择的电脑声卡（WASAPI）→ 与 KDJ 相同的声道对`，然后 Apply。不要替换原来的 master，也不要新增 headphones 到电脑声卡。
5. 开始 KDJ 采集：先确认 Master 有电平，再将播放通道推子拉到底、只开 Cue，确认耳机有声而 KDJ 实时电平静音。恢复推子后应重新收到 Master。停止后的电平不能作为判断依据。

配置表可从「VDJ / Inpulse 500 设置」展开查看。两种接入方式分别记住本面板中的设备选择；返回「常规采集 · 回环 / 输入」仍可使用之前的控制器回环、系统混音或录音输入。设备消失、声道不可用或尚未选择第二路设备时，不允许直接开始，不自动换成麦克风。所有设置只影响 KDJ 的捕获选择，不改 VDJ 配置、Windows 默认设备，也不安装驱动。

第二路输出可能让电脑扬声器实际发声；不要把 Windows 静音作为保证既不出声又能采集的方案。同一播放设备上的通知、浏览器和 KDJ 自身声音也可能进入回环，需避免它们使用该端点。额外输出延迟、Cue 隔离和 ASIO 原主输出不受影响均需真机验证；此入口同样需要按上文完成 WASAPI 捕获标志的真机验收。

参考：[VDJ 的 Master／耳机配置](https://virtualdj.com/manuals/virtualdj/settings/audiosetup/masterheadphones.html)、[Inpulse 500 官方预设](https://virtualdj.com/manuals/hardware/hercules/inpulse500/setup.html)、[VDJ 第二路 Master 讨论](https://virtualdj.com/forums/240138/VirtualDJ_Technical_Support/How_to_output_VirtualDJ_audio_signal_into_OBS__.html)。

## 跟随

复用原有速度估计、调速入口和 100 ms 调度周期，不增加第二套加减速循环。只有偏差至少 120 ms、连续观察至少 2.5 秒且有至少 12 个不同帧的观测、误差方向一致、波动范围不超过 60 ms，才允许启动追齐；近期明显的帧间断也会清空观察。没有节拍证据时，不把“一拍”硬编码为固定时长。

追齐任务按「位置差 = 临时速度差 × 持续时间」计算，临时速度差限制为音乐基准的 ±8%，计划持续 2–7.5 秒。例如基准 1×、稳定落后 0.5 秒时，计划以 1.08× 追齐约 6.25 秒，不再在 1× 和 1.35× 间反复切换。实际收敛仍受解码和识别延迟影响。

执行顺序为：准备/跳转/暂停优先，其次是音乐基准调速，再是临时任务到期恢复，最后才是新的位置追齐。临时补偿结束后先恢复最新音乐基准速度（不是固定 1×），至少留出 2 秒稳定期并重新积累完整观察窗，不能直接续上旧加速。高优先级任务或失锁会停止追齐；剩余偏差重新观察，不排队回放过期指令。

追齐期间若出现超过 120 ms 的帧间断，或最后一帧已超过 250 ms，立即恢复基准速度并禁用追齐 30 秒。冷却期内若仍有稳定偏差，交给备用画面校准，并限制请求频率，避免“加速—卡顿—再次加速”的循环。

没有帧回调时暂停基于帧的纠偏，不把隐藏或遮挡造成的回调缺失当成新的跳转。输出控制保持原有 100 ms 周期；继续使用系统解码器和共享视频调度。

## 仪表

“救场定位”和“循环跟随”只显示已有状态，不参与识别或控制。面板每 500 ms 读取状态，输出测量约每秒上报；仪表不另开逐帧动画循环。

“循环跟随”指持续跟随当前定位，不推断或预测 DJ 的 Loop 回绕。相似度不是正确率，检索耗时不是端到端切入延迟。没有有效帧反馈时不显示伪造的同步误差。

主界面不滚动显示日志；折叠诊断保留复制有界会话记录的入口。
